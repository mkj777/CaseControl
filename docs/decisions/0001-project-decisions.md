# ADR 0001: Project decisions (taken by the owner on 2026-11-06)

Status: accepted. Source: question rounds in the planning session; research in `docs/research/`.

| # | Decision | Choice | Consequence |
|---|---|---|---|
| 1 | Language | Rust (owner's request) | Cargo workspace, MSVC toolchain. |
| 2 | Hardware access tier for v1 | User-mode only (USB HID, NvAPI). SMBus/PawnIO is a later tier. | A `Backend` boundary must exist so an SMBus backend can be added without touching drivers or UI. No kernel code, no admin requirement in v1. |
| 3 | Process shape | One Tauri 2 process: Rust backend holds devices, WebView2 UI, minimizes to tray. No Windows service. The device engine never runs without the process. | Autostart via HKCU Run key. Single instance via named mutex. |
| 4 | License / code reuse | Private, no publication planned. OpenRGB (GPLv2) and liquidctl (GPLv3) code may be ported freely. | If the project is ever published it must be GPL. `reference/openrgb/` holds copied sources. |
| 5 | Logitech / LampArray | Direct Logitech HID (HID++ 2.0, Lightspeed). Not a Dynamic Lighting provider. | Conflict view must list G HUB, `logi_lamparray_service` and Windows Dynamic Lighting as competitors. No MSIX requirement. |
| 6 | HID layer | `hidapi` crate for I/O plus own hot-plug via `CM_Register_Notification` (windows crate). | Shared opens (hidapi default). Device enumeration and hot-plug live in one crate. |
| 7 | Frontend | Vue 3 + TypeScript, Vite, pnpm. | Tauri 2 app with `tray-icon` feature. |
| 8 | Core data model | Designed by the orchestrator (owner delegated: "mach du alles"). Mirrors OpenRGB's RGBController semantics in idiomatic Rust. | See `docs/architecture.md`. |
| 9 | v1 devices | MSI Mystic Light `1462:7D75` (board + ARGB headers), Wooting 60HE ARM `31E3:1310`, Logitech G560 `046D:0A78`, Logitech PRO Wireless via Lightspeed receiver `046D:C539`, RTX 5080 Founders Edition (`10DE:2C02`, subsys `10DE:2095`) via NvAPI Illumination. | Each is a driver module in `cc-drivers`. |
| 10 | Config format | TOML under `%APPDATA%\CaseControl`. | `toml` + `serde`; comments preserved where edited in place. |
| 11 | Repository / CI | Private GitHub repo, GitHub Actions on `windows-latest`: fmt, clippy, nextest, cargo-deny, pnpm typecheck + build, Tauri build artifact. Pinned action SHAs, minimal permissions, branch protection on main. | Release = installer artifact from CI. |
| 12 | Conflict view powers | Show findings and, on explicit click, terminate a process or stop a service (service stop triggers UAC). No automatic intervention, no autostart changes. | Actions are opt-in per click and logged. |
| 13 | Non-goals | No community features, no ads, no telemetry, no network calls, no account, no game integrations, no effects marketplace. | `cargo-deny` bans HTTP client crates; the app never opens a socket. |
| 14 | UI language and names | English. Pages: Devices, Profiles, Conflicts, Settings. Tray menu: Show, Apply profile, Release devices, Quit. | No translation layer in v1. |
| 15 | Visual direction | Dark and spacious: few large elements with generous spacing, the device preview is the focus. | More scrolling, less information at a glance. Details are settled with the owner when the Devices page is built. |
| 16 | Product name | CaseControl. | Window title, tray, installer and `%APPDATA%\CaseControl`. Crate prefix `cc-` stays. |
| 17 | RAM | The Kingston DDR5 sticks have no RGB (owner confirmed). | Nothing on this machine needs SMBus. The PawnIO tier stays a design boundary only and has no planned work. |
| 18 | Devices page layout | Overview grid of device tiles; clicking a tile opens that device full-size in its own view with a back arrow. (2026-11-16) | Two views: overview and device detail. |
| 19 | Colour granularity | Down to single LEDs: whole device, zones, and LEDs selected in the preview. (2026-11-16) | Engine keeps a per-LED buffer; profiles store full buffers. |
| 20 | Colour picker | Swatches for quick clicks, a free picker (saturation/value area + hue bar + hex) that folds out below. (2026-11-16) | Custom component, no UI library. |
| 21 | When changes reach hardware | Live while dragging, throttled to the frame rate. No apply button. (2026-11-16) | Engine coalescing is the throttle. |
| 22 | LED selection | Click selects one LED, dragging sweeps several, Ctrl-click adds. The chosen colour applies to the selection. (2026-11-16) | |
| 23 | Accent colour | Neutral: whites and greys only; device colours in the previews are the only colour in the UI. (2026-11-16) | |
| 24 | Startup behaviour | The last applied profile is applied again on start. Without one, devices stay in hardware mode until the user acts. (2026-11-16) | `last_profile` in settings is set on every apply. |
| 25 | Hardware effects in v1 | Yes: per device a mode menu with speed, brightness, direction and colours as far as the device supports them. (2026-11-16) | |
| 26 | Hiding devices and zones | Right-click hides a device (overview tile) or a zone (device view). Hidden means not controlled: a hidden device is released and keeps its own lighting, a hidden zone gets black in direct colour. (2026-11-16, after the first hardware test: JRGB1/2 and JRAINBOW2 are empty headers) | Stored in settings per device id and zone name. Hardware modes act on the whole board and cannot skip a zone. |
| 27 | Bringing hidden things back | A "Show hidden" toggle in the overview and in the device view shows hidden items greyed out; right-click there unhides. (2026-11-16) | |
| 28 | Layout | Overview tiles fill the window width; the device preview scales with the window instead of a fixed size. Select all / none sits above the preview card. (2026-11-16) | |
| 30 | Design system | `docs/design-system.md` + `apps/desktop/src/tokens.css`, structure modelled on redpanda (role tokens, one primitives folder). Owner choices: neutral greys without a cool tint; one muted red for Faulted / errors / danger and a muted amber for warnings (amends #23: these are the only non-grey UI colours); radius 6/10/18; type 13/15/18/28; controls 36 px; text pages max 760 px, device pages fluid to 1440 px; fields with a subtle border plus a lighter fill (accepted below the WCAG 3:1 control-edge target); all other open points as the draft's option A. (2026-11-16) | Adopted after the phase 3 hide/layout/frame work is merged, in the draft's migration order. |
| 31 | Conflicts at startup and autostart (amends #12) | On every start CaseControl scans for conflicts. RGB suites (OpenRGB, SignalRGB and similar full suites) that affect a detected, non-hidden device are listed in a start dialog saying CaseControl will close them: per program "Close now" (running processes and services) and "Turn off autostart", both preselected; buttons Proceed and Not now; per program "Don't ask again" (it then only shows on the Conflicts page). Vendor tools (G HUB, Wootility, MSI Center, LampArray service ...) never appear in the dialog, only on the Conflicts page. Autostart is turned off reversibly: app entries through the same StartupApproved switch Task Manager uses, services set to Manual; the Conflicts page offers Re-enable. While a dialog-eligible program still has autostart on, the app shows a persistent hint. Nothing is closed or changed without the user's click; there is no automatic proceed. (2026-11-16) | One Proceed causes at most one UAC prompt. Software that affects no detected device is ignored. |
| 32 | Conflict details after review (2026-11-16) | MSI Center counts as a suite (start dialog). Re-enable for app autostart entries switches on every matched entry of that program, also ones turned off in Task Manager. Text is not selectable except in fields, error messages, device ids and conflict evidence (paths, commands). Installer stays per-user. | Per-user install accepted although the self-elevating exe lives in a user-writable folder. |
| 33 | Brightness and all off (2026-11-16) | Device view: a brightness slider at the top, a software dimmer (0-100 %) that scales the device's colours; in a hardware mode the same slider drives the mode's brightness where the device has one. Devices overview: master brightness (multiplies every device), an All off / on switch, Release all. All off and on always fade (no hard cut). Everything persists: device brightness belongs to the profile, master brightness and the off state survive a restart. | No Windows service: #3 stays, CaseControl remains a lightweight per-user app with as few rights as possible (owner, 2026-11-16). The pre-login goal ("PC on, profile shows before login") is to be reached by saving to the hardware where it works; how is being researched and tested. |
| 34 | Saving lighting to the hardware (2026-11-16, direction only) | Goal: from power-on the hardware shows the last state as closely as possible, and every hand-over is smooth. CaseControl writes the board flash once on Quit, logoff or shutdown, and only when the state differs from what is saved; brightness is baked into the saved colour (hardware brightness stays 100 %). Not built until the MSI flash test plan (`docs/research/hardware-persistence-and-service.md` §1.5) has run with the owner; the owner postponed that test. | Mixed per-LED colours on one header can only be approximated by one colour; the mapping is still open. |
| 35 | All off removed (amends #33, 2026-11-17) | All off is gone. Brightness 0 (device or All brightness) is the off state. The overview toolbar has Connect all, All brightness, Release all, Show hidden, Rescan. | `all_off` in old config files is ignored and dropped on the next save. |
| 36 | Takeover default, toasts, conflicts list (2026-11-17) | Taking over a device uses its stored setting, else its hardware readback, else a default colour set in Settings (white by default). Hiding a driven device and Release all show a toast at the bottom right for 5 s ("Device released", "N devices released"). Conflicts is a list with one compact row per program that expands to details. Rescan makes the page inactive while it runs. | Every non-faulted, non-hidden device can be taken by Connect all and by brightness. |
| 37 | Lighting page, fallback colour, settings cleanup (2026-11-17, amends #14, #36) | The Devices page is renamed Lighting. Connect all is renamed Take over all. The default colour is renamed fallback colour and moves from Settings into the Lighting toolbar, as a colour circle next to Take over all with a "?" whose hover text explains it. In colour pickers, the "Custom colour" text button becomes a circle with an eyedropper icon. Settings loses the Hide to tray button, the Conflicts group (OpenRGB port check toggle) and the hint texts under Start with Windows and Device detectors. The sidebar shows the app icon next to the name and the version at the bottom left. The RTX 5080 FE lighting is white only (owner): it is controlled by brightness alone. | The Conflicts page gets a minimal, responsive redesign by a separate agent. |
| 38 | Own lighting after a per-LED start (2026-11-17) | If the MSI board is found in per-LED mode at start, CaseControl restores the last good own lighting it saw for that board (stored per device id in `%APPDATA%\CaseControl\hardware-state.toml`), not static colours. Release also runs for faulted devices and before a re-detected device is reopened; brightness 0 on Mystic Light uses Static at brightness 0 instead of per-LED black. | Nothing is written to flash (#34 stays unbuilt). |
| 39 | Releases and auto-update (2026-11-18, amends #4, #11, #13) | Version 0.1.0 is released on GitHub. The repository becomes public (so the app can fetch releases without a token) and the code is published under GPL-2.0-or-later. The app uses the Tauri updater plugin: it checks GitHub releases, downloads a signed update in the background and installs it silently on the next quit or restart. This is the only network access; reqwest is allowed for the updater only. | Releases are built and signed in CI from a version tag; the updater signing key lives in a CI secret. A pre-publication audit of the repository history runs before the repository is made public. |
| 40 | Always one active profile, autosave (2026-11-18, amends #24, #33) | There is always exactly one active profile; on first start (or when none exists) it is created as "Profile 1" from what the devices show now. Every change (device setting, device brightness) is saved to the active profile at once; there is no Save button. A new profile is empty and named "Profile N" (next free number); any profile can be duplicated; all can be renamed; the last profile cannot be deleted, deleting the active one activates another. Profiles are picked and managed in a dropdown in the Lighting toolbar; the Profiles page is removed. The tray keeps switching profiles. | Global per-device overrides (hidden, zone sizes) and the fallback colour stay outside profiles. |
| 41 | Update buttons, one takeover toggle, toolbar order, per-LED white brightness (2026-11-18, amends #37, #39) | Settings has "Check for updates" (checks and downloads now, shows the status: up to date / version X ready / error) and "Update now" (enabled only when an update is downloaded; installs it and restarts the app). Take over all and Release all become one button: it shows "Take over all" while any visible device can still be taken over, else "Release all". Lighting toolbar: profile dropdown, the takeover button, Show hidden and Rescan on the left; All brightness and the fallback colour (with its "?") on the right. Brightness-only devices (RTX 5080 FE, 3 white LEDs) get one brightness slider per LED/zone on the device page; the device brightness slider still scales all. | The per-LED white level is stored like any per-LED setting (in the active profile). |
| 42 | Colours across shutdown, sign-out and start (2026-11-27, amends #3, #33, #34, #38) | On Windows shutdown or restart CaseControl keeps the current colours (no hand-back); explicit Quit still hands back. Sign-out keeps the colours too, as a setting ("Keep colours when signing out", on by default). Autostart uses a per-user Task Scheduler logon task instead of the HKCU Run entry, and every device gets its profile setting as soon as it is found. Optional "Apply colours before sign-in": a Task Scheduler start-up task, created and removed through the elevated helper (one UAC prompt each), runs CaseControl headless as the signed-in user with a limited token (never SYSTEM or highest privileges), applies the active profile and exits without hand-back. Optional "Save colours to the devices" builds #34 for every device whose driver can save (today MSI Mystic Light and Logitech G560), with no device names in the setting: mixed colours of one zone are saved as their average (linear RGB), brightness baked in; written on enabling and at Quit, sign-out and shutdown only when changed, never on live edits; the device's original saved state is backed up before the first write and written back when the setting is turned off; a device whose original state cannot be read completely is not written. Settings: group Startup gets the before-sign-in switch, a new group Hardware holds the sign-out and save switches; no confirmation dialog, hint text only. | ADR #3 now allows an optional, user-level pre-sign-in task (still no service). Task Manager's Startup apps no longer lists CaseControl. The uninstaller removes the tasks and restores saved devices (best effort, one UAC prompt only if the start-up task exists). The per-user install risk accepted in #32 (malware already running as the user swaps the exe or plants a DLL before an approved UAC prompt) now also covers the before-sign-in on/off and uninstall prompts; accepted again by the owner on 2026-11-27. |
| 29 | Window frame | No Windows title bar. App name at the top of the sidebar, minimise / maximise / close at the top right over the content, the top edge drags the window. Close hides to tray as before. (2026-11-16) | |

No owner decisions are open. Implementation starts only after the owner's explicit go.
