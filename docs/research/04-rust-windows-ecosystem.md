# Research report: Rust tray-resident RGB controller on Windows 11

Facts as of 2026-11-06. Versions/dates from the crates.io API; qualitative claims from docs.rs, upstream READMEs/source, or Microsoft Learn. Items not confirmed against a primary source are marked UNVERIFIED. Open-issue counts are given only where fetched (hidapi-rs 14, cargo-wix 31, cargo-packager 28); issue trends over time were not assessed. No stack recommendation is made.

Tradeoffs: hidapi is the only widely used option that answers every column "yes" except hot-plug and configurable share mode; its `windows-native` feature removes the C toolchain dependency but drops `get_input_report`. async-hid is the only crate with built-in HID hot-plug and feature reports, but is young and thinly used. Windows reserves keyboard/mouse top-level collections absolutely, and (since 1903) blocks U2F usage pages unless the process is elevated; no user-mode library gets around that. Composite Corsair/NZXT devices: select by `interface_number`/`usage_page` with hidapi, or by usage with async-hid.

## 2. Windows platform access

- [`windows`](https://crates.io/crates/windows) 0.62.2 vs [`windows-sys`](https://crates.io/crates/windows-sys) 0.61.2 (both 2025-10-06, MIT/Apache-2.0, [repo](https://github.com/microsoft/windows-rs)). Per-namespace cargo features (`Win32_Devices_HumanInterfaceDevice`, `Win32_Devices_DeviceAndDriverInstallation`, `Win32_UI_Shell`...). `windows` = typed, `Result`/HRESULT, RAII, COM refcounting; `windows-sys` = raw FFI, faster compile. Sub-crates jumped to 0.100 (`windows-registry` 0.100.0, 2026-09-03); the main crates have not. Release 74 (Sep 2026) shipped no new `windows`/`windows-sys`.
- [`wmi`](https://crates.io/crates/wmi) 0.18.4 (2026-03-27, MIT/Apache-2.0): serde-based WMI queries (e.g. `Win32_BaseBoard` for board model); requires COM init; standard classes need no elevation.
- [`winreg`](https://crates.io/crates/winreg) 0.56.0 (2026-03-14, MIT) or Microsoft's [`windows-registry`](https://crates.io/crates/windows-registry) 0.100.0. HKCU Run key needs no elevation; HKLM does.
- [`windows-service`](https://crates.io/crates/windows-service) 0.8.1 (2026-05-08, MIT/Apache-2.0, Mullvad): service install/control requires elevation.
- [`sysinfo`](https://crates.io/crates/sysinfo) 0.40.1 (2026-10-30, MIT): process enumeration works unelevated; other users' process details may be partial.
- Elevation: HID user-mode I/O needs none. SMBus/I2C (motherboard, DRAM) needs a kernel driver: OpenRGB's WinRing0 was quarantined by Defender in 2025 and OpenRGB 1.0 moved to PawnIO, which needs admin or its own background service.

## 4. Process architecture

- IPC: [`interprocess`](https://crates.io/crates/interprocess) 2.4.7 (2026-10-23, 0BSD/Apache-2.0) local sockets = named pipes on Windows, optional tokio; `tokio::net::windows::named_pipe` ([tokio](https://crates.io/crates/tokio) 1.54.1, 2026-10-21) with `ServerOptions`/`ClientOptions` and security descriptors; local TCP (works, but firewall prompts and any local process can connect); [`tonic`](https://crates.io/crates/tonic) 0.14.9 (2026-10-29; repo now `grpc/grpc-rust`) over TCP or named pipe; [`tarpc`](https://crates.io/crates/tarpc) 0.38.0 (2026-08-12). Named pipes support ACLs; TCP needs its own auth.
- Single instance: `CreateMutexW` on a named mutex (`Local\` or `Global\`) via `windows`; [`single-instance`](https://crates.io/crates/single-instance) 0.3.3 wraps it but last release 2021-12.
- Autostart: HKCU `...\CurrentVersion\Run` ([`auto-launch`](https://crates.io/crates/auto-launch) 0.6.0, 2026-01-10; fork `auto-launcher` detects Task Manager disable), Task Scheduler (can run elevated without UAC prompt; needs admin to register), Windows Service (session 0: no tray icon, no desktop; CreateFile on a HID device-interface path has no documented session requirement, but "service opens HID in practice" is UNVERIFIED here).
- Prior art: OpenRGB (GPL-2.0, [GitLab](https://gitlab.com/CalcProgrammer1/OpenRGB)) "can operate standalone or in a client/headless server configuration" with a network SDK interface (in-process, default port 6742: UNVERIFIED); a Linux service is documented, a Windows service/background-process option is discussed but its status is UNVERIFIED; internal process structure not described in the README. SignalRGB ([docs](https://docs.signalrgb.com/troubleshooting/software-conflicts/signalrgb-services/)): `SignalRgbService` (handles device communication) + `SignalRgbLauncher.exe` + `SignalRgb.exe` UI in `%LOCALAPPDATA%\VortxEngine`; UI tech UNVERIFIED.

[`directories`](https://crates.io/crates/directories) 6.0.0 (2025-01-12) maps `%APPDATA%`/`%LOCALAPPDATA%`.
- [`tracing`](https://crates.io/crates/tracing) 0.1.44 + [`tracing-appender`](https://crates.io/crates/tracing-appender) 0.2.5 (2026-04-17; rolling files, non-blocking writer). [`thiserror`](https://crates.io/crates/thiserror) 2.0.21 (library errors), [`anyhow`](https://crates.io/crates/anyhow) 1.0.104 (binary).
- Device loop at 30-60 fps: hidapi/windows-rs calls are blocking; under tokio they need `spawn_blocking` or a dedicated thread per device. Plain threads: one writer thread per device (or one shared thread with a ~16 ms tick), channel-fed, no runtime; tokio buys timers/IPC multiplexing in the same process at the cost of a runtime. async-hid is natively async on Windows.

## 6. Packaging and signing

- [`cargo-wix`](https://crates.io/crates/cargo-wix) 0.3.9 (2025-03-13, MIT/Apache-2.0): WiX v3 (default, EOL upstream) and v4+; `cargo wix sign` wraps signtool; 31 open issues. [`cargo-packager`](https://crates.io/crates/cargo-packager) 0.11.8 (2025-11-27): NSIS + WiX MSI, updater crate, no MSIX, no signing documented; 28 open issues. [Inno Setup](https://jrsoftware.org/isinfo.php) (Inno Setup License, free incl. commercial use): script-driven EXE installer, not Rust-aware, signtool hook via `SignTool` directive. [MSIX](https://learn.microsoft.com/en-us/windows/msix/) (Microsoft docs): package must be signed; Store re-signs for free, but Store distribution is a separate track; neither cargo-wix nor cargo-packager emits MSIX.
- Signing ([Microsoft comparison, 2026-08](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)): unsigned EXE = "strong SmartScreen block; enterprises may block entirely". OV $150-300/yr, EV $400+/yr; hardware key mandatory for both since June 2023; **EV lost instant SmartScreen reputation in 2024**, reputation now accrues per publisher identity for all options. Azure Artifact Signing (formerly Trusted Signing) ~$9.99/month Basic, no token, CI-friendly; organizations eligible in USA, Canada, EU, UK (+AU, NZ, JP, KR, SG, CH, NO, IL per [quickstart](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart)); individuals USA/Canada only. SignPath Foundation signs qualifying open-source projects free.

## 7. Testing and CI

- GitHub Actions `windows-latest` (consider pinning `windows-2022`): [`Swatinem/rust-cache`](https://github.com/Swatinem/rust-cache) v2.9.3 (2026-10-20); `actions-rust-lang/setup-rust-toolchain`; `taiki-e/install-action` with `tool: nextest` ([cargo-nextest](https://crates.io/crates/cargo-nextest) 0.9.151, 2026-11-03; no doctests, add `cargo test --doc`); `cargo clippy -D warnings`, `cargo fmt --check`; [`cargo-deny`](https://crates.io/crates/cargo-deny) 0.20.2 (`EmbarkStudios/cargo-deny-action@v2`: advisories, licenses, bans, sources) and/or [`cargo-audit`](https://crates.io/crates/cargo-audit) 0.22.2. Pin action SHAs, minimal `permissions:`.
- Hardware-free HID tests: a `trait HidTransport { write, read_timeout, send_feature, get_feature }` with a real backend and a scripted fake; protocol code tested against recorded transcripts (hex dumps captured via Wireshark USBPcap or a logging wrapper around the real backend), replayed as request/response fixtures; property tests for packet framing; the fake asserts byte-exact output reports so CI on runners without devices covers the protocol layer. The Win32 enumeration/hot-plug layer stays behind the trait and is covered only by manual or self-hosted-runner tests.
